# jp-bizdoc スライド構成パターン

資料の目的に応じて3パターンから選び、まず章立て(スライドタイトルの一覧)だけを提示して依頼者の合意を取ってから、各スライドの中身を作る。

## 共通原則

- **1スライド1メッセージ**: 1枚に複数の主張を詰め込まない。伝えたいことが2つあれば2枚に分ける。
- **メッセージラインは文で書く**: スライド上部の見出し(メッセージライン)は「◯◯の状況」のような体言止めではなく、
  「◯◯は前月比◯%増加した」のように、そのスライドの結論・主張を一文で言い切る。体言止めは「何が言いたいか」を読み手に推測させてしまう。
- **根拠のない形容詞を使わない**: 「大幅に」「順調に」「多くの」のような、数値や事実の裏付けがない形容詞・副詞は使わない。
  必ず具体的な数値・比較対象(前月比・前年比・目標比など)とセットで書く。

## 1. 結論先行型(報告・提案向け)

表紙 → 結論(1枚) → 根拠(2〜3枚) → 詳細データ → 依頼事項 の順に構成する。

PREP 構造(Point 結論 → Reason 理由 → Example 具体例・データ → Point 結論の再提示)に対応させ、
最初のスライドで結論を言い切ってから根拠を積み上げる。忙しい決裁者が冒頭数枚だけ見ても判断できる構成にする。

| スライド | 内容 |
|---|---|
| 表紙 | 資料タイトル・日付・作成者・提出先 |
| 結論 | 主張したい結論を1枚・一文で(例:「◯◯案の採用を提案する」) |
| 根拠(2〜3枚) | 結論を支える理由を1枚1論点で(市場動向、コスト比較、リスク評価 等) |
| 詳細データ | 根拠の裏付けとなる数値・グラフ・調査結果 |
| 依頼事項 | 相手に求めるアクション(承認・意見・次回までの宿題 等) |

## 2. 経緯報告型(トラブル・障害向け)

事象サマリ → 時系列 → 原因 → 暫定対応/恒久対応 → 再発防止策 の順に構成する。

トラブル報告は「何が・いつ・なぜ起きたか」を先に固め、対応の妥当性を後から示す。暫定対応(応急処置)と
恒久対応(根本解決)を明確に分けて記載し、混同しない。

| スライド | 内容 |
|---|---|
| 事象サマリ | いつ・何が・どの範囲で発生したかを1枚で要約 |
| 時系列 | 発生から現在までの対応履歴を時刻順に列挙(表形式が読みやすい) |
| 原因 | 直接原因と、必要に応じて根本原因(なぜなぜ分析 等)を分けて記載 |
| 暫定対応 / 恒久対応 | 暫定対応(応急処置・現在の状態)と恒久対応(再発を防ぐ恒久的な対策)を分けて記載 |
| 再発防止策 | 恒久対応を踏まえた仕組み・ルール面の対策と、実施予定時期 |

## 3. 比較検討型(選定・稟議付議向け)

目的・要件 → 選択肢一覧 → 比較表(評価軸×案) → 推奨案と理由 → コスト・スケジュール の順に構成する。

比較表は必ず「評価軸(行)× 選択肢(列)」の形式で作り、評価軸を先に固定してから各案を当てはめる。
評価軸を後から追加すると、特定の案に有利なように軸を選んだと受け取られかねないため、要件定義の段階で軸を確定させる。

| スライド | 内容 |
|---|---|
| 目的・要件 | 何のために選定するか、必須要件・希望要件を整理 |
| 選択肢一覧 | 比較対象となる案(製品・ベンダー・方式 等)を列挙 |
| 比較表 | 評価軸(コスト・機能・導入期間・実績 等)× 各案で採点・比較 |
| 推奨案と理由 | 比較表の結果を踏まえた推奨案と、その根拠を一文で |
| コスト・スケジュール | 推奨案の費用感と導入スケジュール(概算で可) |
