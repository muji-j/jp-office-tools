# jp-mail 日程調整

会議・打合せの日程調整メールを「候補提示(複数案)→調整→確定→リマインド」の4段階で進めるための文型集。
敬語の正確さ・AI っぽさの回避は[mail-toolkit.md](mail-toolkit.md)と同様に
[keigo.md](../../jp-bizdoc/references/keigo.md)・[anti-ai.md](../../jp-bizdoc/references/anti-ai.md)を併用する。
書き出し・結びを画一化しない方針も他の用件別定型と同じ。

## jp-dates との連携(原則)

日程調整の文面には「◯営業日後」「今月末」「来週の半ばあたり」のような相対表現がしばしば出てくるが、
日付計算は暗算せず、必ず `jp-dates` スキルのスクリプトに委ねて実日付に変換してから文面に反映する
(計算ロジック自体は本ファイルの管轄外)。

| 相対表現 | 変換方法 | コマンド例 | 文面への反映例 |
|---|---|---|---|
| ◯営業日後 | 営業日ベースで加算 | `python "${CLAUDE_PLUGIN_ROOT}/scripts/jp_dates.py" addbiz 2026-07-11 3` | 「3営業日後(7月15日(水))」 |
| 今月末 | 当月末日を暦日で特定し、休日なら`holiday`で確認 | `python "${CLAUDE_PLUGIN_ROOT}/scripts/jp_dates.py" holiday 2026-07-31` | 「今月末(7月31日(金))」 |
| 今月末の営業日ベースで | 月末日が休日の場合、直前営業日に丸める | `addbiz 2026-07-31 -1`(月末が休日のとき) | 「今月末の営業日(7月30日(木))」 |
| 来週の◯曜日 | 暦日から曜日を特定し、祝日でないか確認 | `python "${CLAUDE_PLUGIN_ROOT}/scripts/jp_dates.py" holiday 2026-07-16` | 「来週木曜日(7月16日)」 |
| ◯営業日前(リマインド送付日の逆算) | 確定日から営業日ベースで減算 | `addbiz 2026-07-16 -1` | (本文には出さず、送付タイミングの内部計算に使う) |

- 文面には相対表現だけを残さない。「来週木曜日(7月16日)」のように、括弧で実日付(曜日つき)を必ず併記する。相手が転記・カレンダー登録する際に誤読が起きないようにするため。
- 遠い将来の日程で祝日を跨ぐ場合は、`jp-dates`の鉄則(祝日データはライブラリ更新に依存)に従い、必要に応じて「現行法令ベース」である旨を候補提示の際に一言添えるか、依頼者に確認する。
- Python 実行環境がない場合は計算を断定せず、`/jp-office-setup` の案内に従う。

## 進め方(4段階)

候補提示(複数案)→調整→確定→リマインドの順で進める。相手の都合が最初から分かっている場合(電話・口頭で仮押さえ済みなど)は候補提示を省略して確定から始めてよい。

### 1. 候補提示(複数案)

一方的に1つの日時を指定するのではなく、複数案を挙げて相手に選んでもらう。目安は3案(2案では選択の余地が狭く、4案以上は相手の検討負担が増える)。

**書き出し(複数案)**
- 「◯◯の件で、日程調整のご相談です。」
- 「◯◯につきまして、下記の候補日で調整させていただきたく存じます。」
- 「恐れ入りますが、次のいずれかでご都合はいかがでしょうか。」

**候補列挙の型**
```
以下の候補日から、ご都合のよい日時をお知らせいただけますと幸いです。

① 7月16日(木) 14:00〜15:00
② 7月17日(金) 10:00〜11:00
③ 7月21日(火) 15:00〜16:00

いずれも難しい場合は、改めて候補日をご提示いたします。
```
候補の日時は、依頼者から「来週半ばあたりで」等の相対表現で指示された場合でも、そのまま書き写さず
[jp-dates との連携](#jp-dates-との連携原則)に従って実日付に変換してから列挙する。

**オンライン/対面の明記**
- オンライン: 「開催方法はオンライン(Web会議)を予定しております。会議URLは日程確定後に別途お送りいたします。」
- 対面: 「開催場所は◯◯(会議室名)を予定しております。」/「差し支えなければ、貴社にご訪問する形でよろしいでしょうか。」
- 未定の場合: 「開催方法(オンライン/対面)についてもご希望があればお知らせください。」

**結び・選ばせる表現(複数案)**
- 「上記いずれかでご都合のよい日時をお知らせください。」
- 「ご都合が合わない場合は、そちらの候補日を2〜3お知らせいただけますと幸いです。」
- 「恐れ入りますが、◯月◯日までにご返信いただけますと助かります。」

**AIっぽくしないコツ**: 候補を機械的に3つ並べるだけでなく、「①②③のいずれも難しければ〜」のように相手が断りやすい逃げ道を一言添えると威圧感が薄れる([anti-ai.md](../../jp-bizdoc/references/anti-ai.md) #6参照)。

### 2. 調整

候補日がすべて合わない、あるいは一部しか合わないという返信への対応。

**書き出し(複数案)**
- 「ご都合をお知らせいただきありがとうございます。」
- 「候補日のご確認、ありがとうございます。」

**本文骨子**
1. 都合が合わない旨をそのまま受け止める一文(相手を責めない)。
2. 追加の候補日を提示する。前回と重複させず、相手からすでに条件(「火曜以降なら」等)が示されていれば、それを起点に候補を絞る。
3. ここでも相対表現(「来週後半で」等)は jp-dates で実日付化してから提示する。

**再提示の型**
```
かしこまりました。それでは、下記の日程で改めてご提案いたします。

① 7月22日(水) 13:00〜14:00
② 7月23日(木) 10:00〜11:00

いずれもご都合が合わない場合は、恐れ入りますがご都合のよい日時を2〜3お知らせいただけますでしょうか。
```

**結び(複数案)**
- 「お手数をおかけしますが、ご確認のほどよろしくお願いいたします。」
- 「引き続き調整させていただきますので、よろしくお願いいたします。」

**AIっぽくしないコツ**: 調整が長引く場合、毎回同じ謝罪表現(「たびたび恐縮ですが」)を繰り返さず、状況に応じて濃淡をつける([anti-ai.md](../../jp-bizdoc/references/anti-ai.md) #8参照)。

### 3. 確定

**書き出し(複数案)**
- 「日程についてご連絡いただきありがとうございます。」
- 「それでは、下記の日程で確定させていただきます。」

**本文の型(必須要素: 日時・形式・議題・出席者)**
```
下記のとおり日程が確定いたしましたので、ご連絡いたします。

日時: 2026年7月16日(木) 14:00〜15:00
形式: オンライン(Web会議) ※会議URLは前日までに別途お送りいたします
議題: ◯◯について
出席者: 株式会社サンプル 山田太郎 様、佐藤花子(自社側)

ご不明点がございましたらお知らせください。当日はどうぞよろしくお願いいたします。
```
- 日時は候補提示の段階で使った実日付表記(曜日つき)をそのまま引き継ぐ。確定段階で再び相対表現に戻さない。
- オンラインの場合は会議URLの共有タイミング(即時に本文へ記載/前日に別送)を明記する。対面の場合は会議室名または訪問先を明記する。
- 出席者が複数部署・複数社にまたがる場合、社外宛のメールには自社側の役職構成まで詳細に書かない(氏名のみで足りることが多い)。

**結び(複数案)**
- 「当日はどうぞよろしくお願いいたします。」
- 「ご都合に変更がございましたら、お早めにご連絡ください。」

### 4. リマインド

前日リマインドは短く要点のみとし、日時・形式(場所/URL)を再掲する。

**前日リマインドの型**
```
明日のお打ち合わせについて、念のためご連絡いたします。

日時: 2026年7月16日(木) 14:00〜15:00
形式: オンライン(Web会議URL: 前回お送りしたリンクをご利用ください) / 対面(◯◯本社3階会議室)

当日はどうぞよろしくお願いいたします。
```

- 通常は前日(1営業日前とは限らない、暦日の前日)に送る。金曜開催で木曜にリマインドを送るなど、送付タイミングを「確定日の◯営業日前」で機械的に運用する場合は、確定日から`addbiz`で逆算する(例: 1営業日前 = `addbiz 確定日 -1`)。
- 開催方法がオンラインの場合、URLは前回送付済みでも本文に再掲する(相手が過去メールを探す手間を省くため)。URLそのものを再掲しない運用の相手には、その旨(「前回お送りしたリンクをご利用ください」)を明記する。
- 直前の変更・キャンセルの可能性がある相手には、「もしご都合に変更がございましたら、朝までにご一報いただけますと幸いです」等の一文を添える。

## 実務メモ

- 会議室・URLの明示は候補提示の段階から行っておくと、確定メールで慌てて追記する事態を避けられる。
- 相手が社外の場合、開催方法(オンライン/対面)の希望を早い段階で確認しておくと、候補の出し直しを避けられる。
- 半年以上先など遠い将来の日程を祝日ベースで確定する場合は、`jp-dates`の鉄則(祝日データはライブラリ更新に依存)に従い、必要なら「現行法令ベース」である旨を添える。
